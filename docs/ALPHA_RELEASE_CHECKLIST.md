# Alpha Release Checklist

Version: 0.1.0
Last updated: 2026-06-14

Use this for `v0.1.0-alpha.1` and nearby source-available/public-alpha releases. The goal is an
honest GitHub alpha that preserves the current state without implying a notarized
distributable app.

Current live state as of 2026-06-16: no GitHub tag or release has been published. Treat
`v0.1.0-alpha.1` as the next prepared prerelease target until the tag and GitHub prerelease
exist.

## Release Boundary

- Release type: source-available public alpha.
- Allowed to ship with real Google Meet/Zoom proof still in the backlog, as long as
  the release notes say so.
- Not allowed to claim a distributable binary until Developer ID signing, hardened runtime,
  notarization, stapling, and exported-artifact smoke verification exist.
- Keep the app positioned as macOS 26+ and local-first.

## Preflight

- Choose the exact commit to tag. Do not tag an unreviewed dirty worktree.
- Read `CHANGELOG.md`, `docs/PROJECT_GOAL_AND_BACKLOG.md`, `docs/PRIVACY.md`,
  `docs/DEPENDENCIES.md`, and `docs/RELEASE_SIGNING_NOTARIZATION.md` for consistency.
- Confirm the release notes still list the open limitations: real Google Meet/Zoom proof
  deferred, OpenAI live ASR unverified, notes quality unverified in a real meeting, and no
  notarized distributable binary.
- Confirm `debugAudioDump` is off before any release proof run.
- Do not include debug WAVs, diagnostic logs, SwiftData stores, TCC state, Keychain data,
  DerivedData, generated Xcode projects, or `work/` evidence folders in the release.

## Verification

For a source-available alpha, record what was run and what was skipped. The normal narrow
verification set is:

```sh
xcodegen generate
scripts/sync-package-lock.sh --verify
xcodebuild -scheme Transcriber -derivedDataPath build test
xcodebuild -scheme Transcriber -derivedDataPath build analyze
```

Optional proof runs:

```sh
scripts/run-audio-fixture-model-proof.sh
scripts/run-audio-fixture-model-proof.sh --include-local-asr
scripts/gate2-real-meeting-proof.sh start
scripts/gate2-real-meeting-proof.sh summarize
scripts/gate2-real-meeting-proof.sh verify-export /path/to/export.md
```

Real-meeting proof is not required for `v0.1.0-alpha.1`, but if it has not passed,
the release body must say that explicitly.

## Tagging

- Confirm the release commit includes the intended release notes and checklist.
- Create an annotated tag:

```sh
git tag -a v0.1.0-alpha.1 -m "v0.1.0-alpha.1"
git push origin v0.1.0-alpha.1
```

- If the tag must move before publication, delete and recreate it before announcing the
  release. Do not silently retag after publication.

## GitHub Release

- Title: `Transcriber v0.1.0-alpha.1`.
- Mark as a prerelease.
- Use the `CHANGELOG.md` candidate `v0.1.0-alpha.1` section as the release body.
- Include a clear first paragraph: this is source-available alpha, not a notarized
  user-installable binary.
- Link the relevant docs: privacy model, project backlog, dependency management, and release
  signing/notarization plan.

## Asset Policy

- Allowed: GitHub-generated source archives for the tagged commit.
- Allowed for source-available alpha only: a local development/ad-hoc-signed zip generated by
  `scripts/build-alpha-release.sh`, as long as the release body and file name clearly say
  it is not notarized and may be rejected by Gatekeeper.
- Allowed only after review: small redacted evidence summaries that contain no transcript
  text, notes text, API key values, local paths that should stay private, debug WAVs, or
  diagnostic logs.
- Not allowed for `v0.1.0-alpha.1`: unlabeled app bundles, `.xcarchive`, `.dmg`, `.pkg`,
  debug artifacts, SwiftData stores, logs, or DerivedData.
- A binary asset becomes acceptable only after a separate distribution track produces a
  Developer ID signed app with hardened runtime, no `get-task-allow`, successful
  notarization, successful stapling, Gatekeeper acceptance, and a fresh exported-artifact
  smoke run.

## Known Limitations To Keep In The Release Body

- Real Google Meet/Zoom proof is still deferred.
- OpenAI Realtime ASR has not been live-verified with an API key.
- Current local Release artifacts are development/ad-hoc signed and may be Gatekeeper-rejected.
- No Developer ID signed artifact is published.
- No notarized or stapled artifact exists.
- The app remains macOS 26+ and local-first.
